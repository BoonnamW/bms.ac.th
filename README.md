# เว็บไซต์โรงเรียน + ระบบจัดการเนื้อหา (CMS)

Express 5 + SQLite (ในตัว Node 22.5+) + EJS — ติดตั้งง่าย ไม่ต้องมีฐานข้อมูลแยก

## เริ่มใช้งานในเครื่อง (พร้อมข้อมูลจริงของโรงเรียน)

1. ติดตั้ง **Node.js เวอร์ชัน LTS** (22.5 ขึ้นไป) จาก https://nodejs.org
2. ดาวน์โหลดโปรเจกต์ (GitHub → Code → Download ZIP แล้วแตกไฟล์ หรือ `git clone`)
3. เปิด terminal ในโฟลเดอร์โปรเจกต์ (Windows: พิมพ์ `cmd` ในช่องที่อยู่ของ File Explorer แล้วกด Enter) แล้วรัน

```bash
npm install          # ติดตั้งครั้งแรกครั้งเดียว
npm run setup        # นำเข้าข่าว หน้าเว็บ อัลบั้ม เมนู จากเว็บเดิม (ครั้งเดียว — จดรหัสผ่าน admin ที่แสดงไว้)
npm run fetch-media  # (ไม่บังคับ) ดาวน์โหลดรูป/ไฟล์ที่เว็บใช้ ราว 15,000 ไฟล์ (รวมรูปย่อ) จากเว็บเดิมมาไว้ในเครื่อง — รันซ้ำเพื่อทำต่อได้
npm start            # เปิดเว็บ
npm run dev          # (ระหว่างแก้โค้ด) เปิดเว็บแบบรีสตาร์ตเองทุกครั้งที่บันทึกไฟล์
```

- เว็บไซต์: http://localhost:3000
- หลังบ้าน: http://localhost:3000/admin (ผู้ใช้ `admin` — รหัสผ่านสุ่มแสดงตอน `npm run setup` และบังคับเปลี่ยนเมื่อเข้าครั้งแรก)
- ข้อมูลทั้งหมดอยู่ในโฟลเดอร์ `data/` (ฐานข้อมูล) และ `uploads/` (รูป) — สำรองสองโฟลเดอร์นี้ก็พอ
- ถ้าไม่รัน `fetch-media` เซิร์ฟเวอร์จะดึงรูปจากเว็บเดิมมาเก็บไว้ใน `uploads/wp` เองเมื่อมีคนเปิดดูครั้งแรก (ต้องต่ออินเทอร์เน็ต)
- สีเริ่มต้น ชมพู–ขาวเป็นหลัก แซมเขียว: สีหลัก `#e01371` (ปุ่ม เมนูที่เลือก จุดเด่น) · สีพื้นอ่อน `#fef3f6` · สีเข้ม `#0a351d`
  (หัวข้อ แถบบนสุด ส่วนท้ายเว็บ) · สีรอง `#357c53` (ป้ายหมวด วันที่ ไอคอน) — เปลี่ยนได้ที่ หลังบ้าน → ปรับสีเว็บไซต์

ถ้าไม่รัน `npm run setup` ระบบจะเริ่มด้วยข้อมูลตัวอย่างของโรงเรียนสมมติ
(กำหนดรหัสผ่าน admin เองได้ด้วยตัวแปร `ADMIN_PASSWORD` ก่อนรันครั้งแรก)

### อัปเดตเป็นเวอร์ชันใหม่

`git pull` (หรือดาวน์โหลด ZIP ใหม่มาวางทับ **โดยเก็บโฟลเดอร์ `data/` และ `uploads/` เดิมไว้**) → `npm install` → `npm start`
ฐานข้อมูลเดิมจะถูกปรับให้รองรับความสามารถใหม่เองตอนเปิดระบบ ข้อมูลที่แก้ไว้ในหลังบ้านไม่หาย

## จัดการอะไรได้บ้าง (เมนูหลังบ้าน)

- **เนื้อหา:** ข่าวสาร/ประกาศ · ปฏิทินกิจกรรม · ผลงานและรางวัล · หน้าเว็บไซต์ · แกลเลอรี
- **บุคลากรและคณะกรรมการ (หน้าทำเนียบ):** หน้าเว็บใดก็ได้ตั้ง “รูปแบบหน้า” เป็นทำเนียบบุคคลได้ — แสดงการ์ดรูป ชื่อ ตำแหน่ง
  คนบนสุด (หัวหน้ากลุ่มสาระ / ประธาน / ผู้อำนวยการ) มีได้คนเดียวต่อหน้า และตั้งป้ายเองได้ ผู้ดูแลที่เข้าสู่ระบบอยู่จะเห็นปุ่ม
  “เพิ่มรายชื่อในหน้านี้” “ตั้งค่าหน้านี้” และปุ่มแก้ไขบนการ์ดโดยตรง บันทึกแล้วกลับมาที่หน้าเดิม
  (เนื้อหาของหน้าแสดงเหนือรายชื่อ ส่วนที่อยู่หลัง “เส้นคั่น” แสดงใต้รายชื่อ · หน้ารวมทำเนียบแสดงการ์ดของทุกหน้าในกลุ่มเมนูเดียวกัน)
  หน้าทำเนียบผู้บริหารตั้ง “เรียงจากคนแรกถึงคนปัจจุบัน” ไว้ — คนปัจจุบันแสดงท้ายสุด (ตั้งได้ทุกหน้าในฟอร์มหน้าเว็บ)
- **ผลงานและรางวัล:** ผลงานโรงเรียน ครูและบุคลากร และนักเรียนรวมอยู่ในรายการเดียว มีป้ายสีบอกว่าเป็นผลงานของใคร
  แต่ละผลงานมีหน้ารายละเอียด `/awards/<เลขที่>` — ข้อความ (จัดรูปแบบได้) รูปหลัก รูปเพิ่มเติมไม่เกิน 12 รูป หรือโฟลเดอร์ Google Drive
  วันที่และเวลา ผู้ได้รับรางวัล ระดับ เอกสารแนบ (PDF/Word/Excel/PowerPoint เช่น ประกาศผล เกียรติบัตร) และลิงก์ข่าว
  หน้าแรกแสดง 8 ผลงานล่าสุด หน้า `/awards` รวมทั้งหมด แยกตามปี พ.ศ. ค้นหาและกรองตามประเภท/ปีได้
  ผู้ดูแลที่เข้าสู่ระบบอยู่เพิ่ม/แก้ไขได้จากหน้า `/awards` และหน้ารายละเอียดโดยตรง (ชุดเริ่มต้น 17 รายการมาจากข่าวรางวัลของเว็บเดิม แก้ไขหรือลบได้)
- **เบญจมาฯ สาร (E-book รายเดือน):** ครูและผู้ดูแลเขียนบทความในหลังบ้าน → “เบญจมาฯ สาร — บทความรายเดือน” (หัวข้อ หมวด วันที่ ผู้เขียน เนื้อหา
  รูปหลัก รูปประกอบไม่เกิน 12 รูป หรือโฟลเดอร์ Google Drive) และเลือกการจัดหน้า 5 แบบ — รูปใหญ่ด้านบน · รูปข้างข้อความ · เน้นภาพกิจกรรม ·
  ภาพเต็มหน้า · ข้อความล้วน วันที่ 1 ของเดือนถัดไประบบรวมบทความทั้งเดือนเป็นเล่ม (ปก สารบัญพร้อมเลขหน้า ปกหลัง) และเผยแพร่ที่ `/journal` เอง
  อ่านได้แบบพลิกหน้า เลื่อนอ่าน เต็มจอ หรือพิมพ์/บันทึกเป็น PDF ขนาด A4 · ตั้งปก เลขฉบับ บรรณาธิการแถลง คณะผู้จัดทำ
  เผยแพร่ก่อนกำหนดหรือซ่อนเล่มได้ที่ “เบญจมาฯ สาร — เล่มและปก” (ผู้ดูแลเห็นตัวอย่างเล่มเดือนปัจจุบันก่อนเผยแพร่) — เล่มเก่าแบบ AnyFlip/PDF ยังแสดงบนชั้นหนังสือเหมือนเดิม
- **ภาพกิจกรรมจาก Google Drive:** อัลบั้มภาพและข่าวใส่ลิงก์โฟลเดอร์ Google Drive ที่แชร์แบบ “ทุกคนที่มีลิงก์ดูได้” แล้วเว็บแสดงรูปในโฟลเดอร์ให้เอง
  (เปิดดูทีละรูปแบบเต็มจอได้) เพิ่มรูปในโฟลเดอร์ภายหลังได้ เว็บอัปเดตรายการเองทุก 6 ชั่วโมง หรือกด “อัปเดตรูปจาก Drive ตอนนี้”
  เซิร์ฟเวอร์เก็บรูปย่อไว้ใน `uploads/gdrive` ผู้ชมไม่ต้องโหลดจาก Google โดยตรง
- **หน้าแรก:** สไลด์ · เมนูลัด · ตัวเลขความภาคภูมิใจ · หลักสูตรและการเรียนรู้ · จุดเด่นของโรงเรียน
- **จัดเมนูและหน้าแรก (ลากวาง):** จับเมนูลากขึ้น–ลง ลากไปวางใต้เมนูหลักอื่นเพื่อเป็นเมนูย่อย (ชี้ค้างที่เมนูที่ย่ออยู่เพื่อขยาย)
  เพิ่ม แก้ชื่อ/ลิงก์ ซ่อน และลบได้ในหน้าเดียว แล้วกดบันทึกครั้งเดียว — ใช้ปุ่ม ↑ ↓ → ← หรือปุ่มลูกศรบนแป้นพิมพ์แทนการลากได้
  (ถ้ามีคนแก้เมนูจากที่อื่นระหว่างจัด ระบบไม่บันทึกทับ) และเรียงลำดับ/ซ่อนส่วนต่าง ๆ ของหน้าแรกได้ สีพื้นของแต่ละส่วนสลับให้เองตามลำดับ
- **เมนูและบริการ:** เมนูหลักและเมนูย่อย (ชื่อไทย/อังกฤษ ลำดับ ซ่อน/แสดง) · ระบบบริการออนไลน์ (แยกนักเรียน/ผู้ปกครอง/ครู/บุคคลทั่วไป)
- **ป๊อปอัปก่อนเข้าเว็บ:** 3 รูปแบบ — การ์ด (รูป หัวข้อ ข้อความ ปุ่ม) · โปสเตอร์ (ภาพใหญ่เต็มขนาด ตัวอักษรเล็กใต้ภาพ เหมาะกับข่าวสำคัญ) ·
  ไว้อาลัย (พื้นดำ ภาพใหญ่ ตัวอักษรเล็ก พร้อมโบว์ดำ) เลือกขนาดกลาง/ใหญ่/ใหญ่มาก ซ่อนหัวข้อได้ ตั้งวันเริ่ม–หยุดแสดงล่วงหน้าได้
  แสดงที่หน้าแรกทีละอัน (ครั้งเดียวต่อการเปิดเว็บ / วันละครั้ง / ทุกครั้ง) ปิดได้ด้วยปุ่ม “เข้าสู่เว็บไซต์” หรือปุ่ม Esc
  ผู้ดูแลกด “ดูตัวอย่าง” ในรายการป๊อปอัปเพื่อดูหน้าตาจริงก่อนเผยแพร่
- **ช่วงไว้อาลัย:** ติ๊กในป๊อปอัปให้แสดงโบว์ดำที่มุมซ้ายบนของทุกหน้า และ/หรือปรับทั้งเว็บเป็นโทนขาวดำ ตลอดช่วงเวลาที่ป๊อปอัปนั้นเปิดใช้
  (ครบกำหนดหยุดแสดง เว็บกลับเป็นสีปกติเอง)
- **ปรับสีเว็บไซต์:** สีประจำโรงเรียน 4 สี และสีแต่ละส่วน (แถบบนสุด เมนูหลัก ภาพสไลด์ แถบชื่อหน้า พื้นหลังส่วนสลับ ปุ่มหลัก
  แถบเชิญชวน ส่วนท้ายเว็บ) พร้อมตัวอย่างหน้าเว็บที่เปลี่ยนตามทันทีขณะเลือก — ระบบปรับสีให้ตัวอักษรในส่วนนั้นอ่านง่ายเสมอ
  (บอกสีที่ใช้จริงไว้ใต้ช่อง) และมีปุ่มคืนค่าสีเริ่มต้นของโรงเรียน
- **Facebook ที่ส่วนท้ายเว็บ:** เพจ Facebook ของโรงเรียนแบบย่อ (หัวเพจ ปุ่มติดตาม จำนวนผู้ติดตาม) ในคอลัมน์ “ติดตามข่าวสาร” ใช้พื้นที่น้อย —
  ตามหลักความเป็นส่วนตัว เพจโหลดเมื่อผู้ชมกด “แสดง” แล้วจำไว้ครั้งต่อไป (ตั้งให้โหลดทันทีได้ที่ ตั้งค่าเว็บไซต์ → ข้อมูลติดต่อ)
- **ระบบ:** ข้อความจากผู้ติดต่อ · ตั้งค่าเว็บไซต์ (ชื่อ โลโก้ ข้อมูลติดต่อ แถบประกาศสำคัญ ลิงก์ Facebook/LINE/YouTube แผนที่)
- รายการในหลังบ้าน (ข่าว หน้าเว็บ อัลบั้ม ผลงาน บทความ) มีปุ่ม “ดูบนเว็บ” เปิดหน้าจริงของรายการนั้น
- หลังบ้านใช้บนโทรศัพท์ได้ (เมนูด้านข้างย่อเป็นปุ่ม “เมนู”)
- แดชบอร์ดแสดงกิจกรรมที่กำลังจะมาถึง และความพร้อมของหัวข้อ ITA / OIT ที่ยังรอข้อมูล

## ความสามารถแบบเว็บแอป

- **ติดตั้งบนโทรศัพท์ได้ (PWA)** — มีไอคอนโรงเรียนบนหน้าจอ เปิดหน้าที่เคยดูได้แม้ไม่มีอินเทอร์เน็ต (ต้องเปิดผ่าน HTTPS หรือ localhost)
- **ปฏิทินออนไลน์** — ผู้ปกครองกดติดตาม (`/calendar.ics`) ครั้งเดียว กิจกรรมใหม่ขึ้นในปฏิทินโทรศัพท์เอง หรือเพิ่มทีละกิจกรรมลง Google Calendar
- **ค้นหาด่วน** (Ctrl K) พร้อมผลแนะนำขณะพิมพ์ และ **ผู้ช่วยค้นหาข้อมูล** มุมขวาล่าง
- **ศูนย์ข้อมูลสารสนเทศ** (`/data`) กราฟคำนวณจากข้อมูลจริงในระบบ พร้อมตารางข้อมูล
- **ข้อมูลเปิด:** RSS `/feed.xml` · iCalendar `/calendar.ics` · JSON `/api/news` · แผนผังเว็บไซต์ `/sitemap.xml`
- **การเข้าถึง:** ปรับขนาดตัวอักษร โหมดความคมชัดสูง ใช้งานด้วยแป้นพิมพ์ได้ทั้งหมด
- **ความเป็นส่วนตัว:** ไม่มีคุกกี้ติดตาม แผนที่ วิดีโอ และโพสต์ Facebook จากภายนอกโหลดเมื่อผู้ชมกดเองเท่านั้น ตัวนับผู้เข้าชมนับเป็นจำนวนต่อวัน ไม่เก็บข้อมูลส่วนบุคคล

## ความปลอดภัย

| ด้าน | มาตรการ |
|---|---|
| รหัสผ่าน | bcrypt (cost 12), ขั้นต่ำ 10 ตัวอักษร, บังคับเปลี่ยนครั้งแรก, ออกจากอุปกรณ์อื่นเมื่อเปลี่ยน |
| เข้าสู่ระบบ | จำกัด 10 ครั้ง/15 นาที, ล็อกบัญชี 15 นาทีเมื่อผิด 5 ครั้ง, ป้องกัน timing attack, สร้าง session ใหม่ทุกครั้ง |
| Session | คุกกี้ HttpOnly + SameSite=Strict (+ Secure บน HTTPS), เก็บเฉพาะค่าแฮชในฐานข้อมูล, หมดอายุเมื่อไม่ได้ใช้งาน 2 ชม. (ใช้งานอยู่ต่ออายุเอง) |
| CSRF | โทเค็นทุกฟอร์มที่เปลี่ยนข้อมูล (หลังบ้านและฟอร์มสาธารณะ) |
| XSS | EJS escape อัตโนมัติ, เนื้อหา rich text ผ่าน sanitize-html แบบ whitelist, CSP เข้มงวด (ไม่มี inline script) |
| SQL Injection | prepared statements ทั้งหมด, ชื่อคอลัมน์มาจากรายการที่กำหนดไว้เท่านั้น |
| อัปโหลดไฟล์ | ตรวจ "ไบต์จริง" ของไฟล์ — รูป JPG/PNG/WebP/GIF ≤ 5 MB (ย่อในเครื่องก่อนส่ง) · เอกสาร PDF/Word/Excel/PowerPoint ≤ 10 MB, เปลี่ยนชื่อเป็นสุ่ม · ตัดข้อมูลแฝงในรูป JPEG (พิกัด GPS วันเวลา รุ่นกล้อง) ก่อนเผยแพร่ · ไฟล์ที่อัปโหลดเปิดแบบ sandbox รันสคริปต์ไม่ได้ |
| Header | Helmet: CSP (ไม่มี inline script ไม่โหลดสคริปต์/ฟอนต์จากภายนอก), HSTS (production), X-Content-Type-Options, frame-ancestors none, Permissions-Policy |
| ลิงก์ของเว็บ | ตั้ง `SITE_URL` แล้วลิงก์แบ่งปัน แผนผังเว็บไซต์ RSS ปฏิทิน ใช้ที่อยู่นี้เสมอ (ไม่เชื่อ Host header ที่ปลอมได้) |
| ฟอร์มติดต่อ | จำกัด 5 ครั้ง/ชม./IP + honeypot กันบอท |
| URL | รับเฉพาะ `/path`, `http(s)`, `mailto`, `tel` (กัน `javascript:`) |

## ขึ้นใช้งานจริง (Production)

1. ตั้ง `NODE_ENV=production`
2. รันหลัง reverse proxy ที่เปิด **HTTPS** (Nginx / Caddy / Cloudflare) และตั้ง `TRUST_PROXY=1`
3. รันด้วย process manager เช่น `pm2 start server.js`
4. สำรองโฟลเดอร์ `data/` และ `uploads/` เป็นประจำ

ตัวแปรที่ใช้ได้: `PORT`, `NODE_ENV`, `TRUST_PROXY`, `ADMIN_PASSWORD`, `DATA_PATH`, `WP_MEDIA_URL`, `GOOGLE_API_KEY`, `SITE_URL`, `OLD_SITE_URL`

`SITE_URL` (แนะนำเมื่อขึ้นจริง): ที่อยู่หลักของเว็บ เช่น `https://www.bms.ac.th` — ใช้ในลิงก์แบ่งปัน Facebook/LINE แผนผังเว็บไซต์ RSS และปฏิทิน

`OLD_SITE_URL` (ตั้งหลังเปลี่ยน DNS): ที่อยู่ใหม่ของโฮสต์เดิม เช่น `https://old.bms.ac.th` — ใช้แทนชื่อเดิมทั้งไฟล์ WordPress ที่ยังไม่ได้คัดลอก และระบบอื่นบนโฮสต์นั้น

`GOOGLE_API_KEY` (ไม่บังคับ): คีย์ Google Drive API สำหรับอ่านรายชื่อรูปในโฟลเดอร์ — เสถียรกว่าและอ่านวันที่ถ่ายรูปได้
(Google Cloud Console → APIs & Services → เปิด Google Drive API → Credentials → Create API key แล้วจำกัดคีย์ให้ใช้กับ Drive API เท่านั้น)
ถ้าไม่ตั้ง เว็บอ่านรายชื่อรูปจากหน้าแสดงโฟลเดอร์แบบฝังของ Google แทน (ใช้ได้กับโฟลเดอร์ที่แชร์สาธารณะ)

### บนโฮสต์ DirectAdmin / cPanel ("Setup Node.js App" ของ CloudLinux)

- อัปโหลดโค้ดไว้นอก `public_html` (เช่น `~/bms-web`) แล้วสร้างแอป: Node.js 24 · Production · Application startup file `passenger.cjs`
- ตัวแปร: `DATA_PATH` (โฟลเดอร์นอก `public_html` เช่น `~/bms-data`), `SITE_URL`, `ADMIN_PASSWORD`, `TRUST_PROXY=1`
  และถ้าเว็บ WordPress เดิมอยู่บนโฮสต์เดียวกัน `WP_UPLOADS_DIR=<public_html>/bs/wp-content/uploads` (ใช้รูปเดิมได้เลย ไม่ต้องคัดลอก)
- กด Run NPM Install → Run JS script `setup` (นำเข้าเนื้อหาครั้งแรก) → Restart
- ทดสอบที่ subdomain ก่อน (เช่น new.bms.ac.th) แล้วค่อยเปลี่ยน Application URL เป็นโดเมนหลัก
- ก่อนลบโฟลเดอร์ `bs` ของเว็บเดิม: ย้าย `bs/wp-content/uploads` ไปไว้ที่ `<DATA_PATH>/uploads/wp` แล้วลบตัวแปร `WP_UPLOADS_DIR`

## ย้ายข้อมูลจากเว็บ WordPress เดิม (www.bms.ac.th/bs)

`scripts/import-wp.mjs` นำเข้าเนื้อหาที่เผยแพร่แล้วทั้งหมด: ข่าว 440 เรื่อง, หน้าเว็บ, อัลบั้มภาพ (Responsive Lightbox),
เมนู (จัดกลุ่มใหม่ ลึกไม่เกิน 2 ชั้น), หน้า ITA/OIT ที่มีเนื้อหาอยู่แล้ว และลิงก์เดิมทุกลิงก์ (`/bs/ปี/เดือน/วัน/ชื่อข่าว/`, `/bs/?p=123`)
จะถูกส่งต่อ (301) ไปยังหน้าใหม่อัตโนมัติ — รันซ้ำได้ ไม่สร้างซ้ำและไม่ทับสิ่งที่แก้ไขในหลังบ้าน

```bash
# จากไฟล์ส่งออกฐานข้อมูล (phpMyAdmin → Export) — ไฟล์ .sql มีข้อมูลผู้ใช้ ห้าม commit
node scripts/import-wp.mjs bmsacth_benjamadb2019.sql

# สร้างไฟล์เนื้อหาสาธารณะใหม่ (ไม่มีตารางผู้ใช้) สำหรับ seed/ ที่ใช้ตอนขึ้นเซิร์ฟเวอร์
node scripts/import-wp.mjs bmsacth_benjamadb2019.sql --export seed/bms-wp.json.gz
```

**รูปและไฟล์แนบ** ถูกอ้างอิงเป็น `/uploads/wp/<ปี>/<เดือน>/<ไฟล์>`
- ระหว่างย้าย: ไฟล์ที่ยังไม่มีในเครื่องจะถูกส่งต่อไปดึงจากเว็บเดิมอัตโนมัติ (ที่อยู่บันทึกไว้ตอนนำเข้า หรือกำหนดเองด้วย `WP_MEDIA_URL`)
- ย้ายเสร็จ: คัดลอกโฟลเดอร์ `public_html/bs/wp-content/uploads/` ของโฮสต์เดิมไปไว้ที่ `<DATA_PATH>/uploads/wp/` (ประมาณ 6 GB) — ไฟล์ที่มีในเครื่องจะถูกใช้ก่อนเสมอ
- **ต้องคัดลอก (หรือรัน `fetch-media`) ก่อนเปลี่ยน DNS** ของ www.bms.ac.th มาที่เซิร์ฟเวอร์ใหม่ — หลังเปลี่ยนแล้วชื่อเว็บเดิมจะชี้มาที่เว็บนี้เอง ระบบจึงหยุดส่งต่อ (ตอบ 404 แทนการวนไม่รู้จบ) และรูปที่ยังไม่ได้คัดลอกจะไม่แสดง
  ถ้ายังคัดลอกไม่ทัน ให้เปิดโฮสต์เดิมไว้ที่ชื่ออื่น (เช่น `old.bms.ac.th`) แล้วตั้ง `OLD_SITE_URL=https://old.bms.ac.th`
- **ระบบอื่นบนโฮสต์เดิม** (ระบบจองห้อง e-borrow ฯลฯ — รายชื่อโฟลเดอร์ตั้งที่ หลังบ้าน → ตั้งค่า → ระบบบนโฮสต์เดิม): ลิงก์เดิม `www.bms.ac.th/<โฟลเดอร์>/…` ถูกส่งต่อไปยัง `OLD_SITE_URL` (ก่อนเปลี่ยน DNS ส่งไปชื่อเดิม)
  รูปและเอกสารในโฟลเดอร์เหล่านี้ที่เนื้อหาอ้างถึง (เช่น รูปผู้บริหารใน `img/boss`) ระบบเก็บสำเนาไว้ใน `uploads/old` ตั้งแต่เริ่มทำงาน — เปลี่ยน DNS แล้วยังแสดงได้ทันที
- โฟลเดอร์ `uploads/wp` เปิดให้เข้าถึงเฉพาะไฟล์รูป/เอกสาร (jpg png gif webp pdf doc xls ppt zip mp4) เท่านั้น
- รูปจากเว็บเดิมใช้รูปย่อที่ WordPress สร้างไว้ (300/768/1024 px) ผ่าน `srcset` — โทรศัพท์โหลดรูปเล็กลงหลายเท่า (`fetch-media` ดาวน์โหลดรูปย่อให้ด้วย)

lib/session.js   ตรวจการเข้าสู่ระบบ (ใช้แสดงปุ่มแก้ไขบนหน้าเว็บด้วย)
scripts/         import-wp.mjs (นำเข้าจากเว็บเดิม) / add-standard-pages.mjs (หน้า ITA/PDPA)
seed/            เนื้อหาสาธารณะของเว็บเดิม ใช้นำเข้าอัตโนมัติตอนขึ้นเซิร์ฟเวอร์ครั้งแรก
routes/          public.js (หน้าเว็บ) / admin.js (หลังบ้าน)
views/           แม่แบบหน้า (EJS)
public/          CSS / JS / ไอคอนแอป / sw.js (ใช้งานออฟไลน์)

## ขึ้นโฮสต์แบบเดโม (Render)

1. เข้าสู่ระบบ GitHub แล้วสร้าง repository ใหม่ → อัปโหลดไฟล์ในโปรเจกต์ (ยกเว้น `node_modules`, `data`, `uploads`) หรือแตกไฟล์ `school-website-deploy.zip` แล้วอัปโหลดทั้งหมด
2. เข้าสู่ระบบ https://render.com → New → **Blueprint** → เลือก repository นั้น (ระบบอ่าน `render.yaml` ให้เอง)
3. ใส่ค่า `ADMIN_PASSWORD` (อย่างน้อย 10 ตัวอักษร มีตัวอักษรและตัวเลข) แล้วกด Deploy
4. ได้ลิงก์ `https://school-website-xxxx.onrender.com` — ครั้งแรกระบบนำเข้าข้อมูลโรงเรียนให้อัตโนมัติ

ข้อจำกัดของแพ็กเกจฟรี: เซิร์ฟเวอร์จะหลับเมื่อไม่มีคนเข้า (เปิดครั้งแรกช้าราว 30 วินาที) และข้อมูลที่แก้ในหลังบ้านจะ **หายเมื่อรีสตาร์ต**
ถ้าจะใช้งานจริง ให้เปลี่ยนเป็นแพ็กเกจที่มี Persistent Disk แล้วตั้งตัวแปร `DATA_PATH` ให้ชี้ไปที่โฟลเดอร์ที่ mount disk ไว้ เพื่อเก็บฐานข้อมูลและรูปอัปโหลดถาวร
